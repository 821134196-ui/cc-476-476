# 帘务通 · 家政窗帘拆洗与房间复装核验系统

管理从**上门拆卸 → 运输洗护 → 修补 → 烘干配包 → 配送复装 → 验收关单 → 费用复核**
的窗帘洗护全链路。客户信息全部为虚构样例数据。零第三方依赖（Python 3 标准库 + SQLite）。

## 一条本地启动命令

```bash
python3 -m curtainflow
# 打开 http://127.0.0.1:8765
```

启动时自动重建 SQLite 数据库、生成本地拆前/复装后占位照片，并载入样例：
**串包、缩水、染色返工、挂钩缺失赔付、布料禁洗、客户延期、二次修补、复装不平整、
洗护超时与预约临近提醒、关单收款**。

可选参数：`--port 9000`、`--no-demo`（沿用现有数据库）、`--db`、`--photos`。

## 七个产品页面

| 页面 | 内容 |
|---|---|
| 上门拆卸 | 订单、住址代号、预约/延期留痕；按窗位勾选帘片、清点挂钩、装袋封签、发运到厂 |
| 窗位清单 | 订单 → 房间 → 窗位 → 帘片树形清单，每片只显示必要编号（P1…）与状态 |
| 洗护队列 | 到厂入队、48h 时限、禁洗布料仅除尘挂晾、登记损伤/修补、烘干完成 |
| 修补赔付 | 八类异常留痕；客服提交赔付、**客服主管**批准赔付/返工；修补轮次（二次修补自动留痕） |
| 配包配送 | 洗净后按**原窗位**配包、醒目的封签号（非颜色区分）；批次发车/签收（模拟配送适配器） |
| 复装对照 | 扫码校验归属（串包拦截留痕）；**拆前 / 复装后双图对照**，挂钩数量在照片下方；全窗位验收才关单 |
| 费用复核 | 基础洗护费 + 修补/返工费 − 赔付；全窗位验收且无未处理异常才可关单；模拟付款适配器收款 |

## 关键业务规则

- **编号唯一**：帘片编号 `ORD-xxxx-窗位-P序号` 全库唯一（DB 唯一约束）。
- **配包完整**：同一帘片只能归属一个配送包（重复配包/跨窗位串包均被拒绝并留痕）。
- **状态顺序**：帘片 12 态、订单 9 态严格按定义流转，跳步即 409。
- **重复验收**：同一帘片只能有一条 `accepted=1` 复装记录（部分唯一索引 +
  `BEGIN IMMEDIATE`），8 线程并发验收/扫描均只成功一次。
- **赔付权限**：洗护员可登记损伤，客服可提交赔付，**批准赔付 / 批准返工仅客服主管**。
- **复装不平整**：留痕后帘片退回待复装，重新扫描验收；之前的通过不被覆盖。
- **关单门槛**：全部窗位帘片 `accepted`、无 open 异常；付款由财务发起。

## 架构

```
curtainflow/
  db.py          SQLite 建表（唯一性约束落库）
  service.py     领域服务：状态机/权限/配包/复装/赔付/费用/提醒扫描
  photos.py      纯标准库生成确定性 PNG，存放于 data/photos/
  adapters.py    模拟配送、付款适配器
  reminders.py   进程内守护线程（60s 扫描洗护/预约/验收时限）
  seed.py        样例数据（python3 -m curtainflow.seed 可单独运行）
  server.py      http.server：JSON API + 静态页 + 本地照片
  web/           原生 HTML/CSS/JS（亚麻白 / 布艺蓝 / 暖灰）
tests/
  test_rules.py  22 项规则测试（含并发）
```

角色通过页面右上角切换（请求头 `X-Role`）：拆装技师 / 洗护员 / 客服 /
客服主管 / 财务。数据存 SQLite（`data/curtainflow.db`），照片存本地目录
（`data/photos/`），提醒为进程内线程，配送与付款均为进程内模拟适配器。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：编号唯一、配包完整（含串包留痕）、状态顺序、重复验收（顺序+并发）、
赔付/返工权限、二次修补、禁洗拦截、关单与费用。
