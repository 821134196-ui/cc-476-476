# 帘净到家 · 家政窗帘拆洗与房间复装核验系统

管理窗帘 **上门拆卸 → 装袋运输 → 洗护烘干 → 修补 → 按原窗位配包 → 配送 → 逐片复装 → 窗位验收 → 关单** 的全链路。
纯 Python 标准库实现（`http.server` + `sqlite3`），零第三方依赖。

## 一条命令启动

```bash
cd curtaincare
python3 run.py            # 首次自动建库并载入演示样例（串包 / 缩水 / 二次返工）
# 打开 http://127.0.0.1:8000
```

- `python3 run.py --reset` 清空数据重新载入样例
- `python3 run.py --port 8080` 换端口
- 运行测试：`python3 -m unittest discover -s tests -v`（16 项）

## 业务规则要点

| 规则 | 实现 |
|---|---|
| 编号唯一 | 帘片编号 / 袋·包封签号 / 配送批次号均全局唯一（DB 约束） |
| 串包防控 | 帘片 `bag_id` / `package_id` 为单列外键，结构上不可能归入两袋/两包；到厂发现串包可登记留痕并归队 |
| 配包完整 | 窗位全部帘片完工（待配包）才可配包，缺一不可 |
| 状态顺序 | 帘片/窗位/订单三级状态机，非法跳转一律拒绝 |
| 并发复装 | 复装扫描为条件 UPDATE，并发只成功一次；重复扫描报 409 |
| 重复验收 | 已验收窗位不可再次验收；全部窗位验收 + 费用复核后才可关单 |
| 损伤与赔付 | 洗护人员登记损伤；赔付 / 返工仅客服主管可批准（其余角色 403） |
| 异常留痕 | 串包、缩水、染色、挂钩缺失、布料禁洗、客户延期、二次修补、复装不平整全部落 `incidents` |
| 提醒 | 进程内后台线程：洗护 SLA 2h、修补 SLA 1h、复装预约 24h 内提醒，去重可确认 |
| 适配器 | 模拟配送（拒单可注入）与模拟支付（失败可注入），结果落库留痕 |

## 角色

界面右上角切换：**上门/配送员**（拆卸、封袋、运输、复装）、**洗护人员**（洗护、烘干、修补、登记损伤）、**客服主管**（批准赔付/返工、复核费用、收款、关单）。

## 演示样例（种子数据，客户均为虚构）

- **CO-0001 湖畔雅居**：复装验收中 —— 含串包、缩水、二次修补、挂钩缺失留痕
- **CO-0002 云溪别院**：洗护中 —— 含禁洗真丝拦截、染色、损伤待审批（触发洗护 SLA 提醒）
- **CO-0003 梧桐里**：待拆卸 —— 演示预约提醒
- **CO-0004 汀兰苑**：已完成闭环 —— 含赔付、收款、关单

## 目录

```
curtaincare/
├── run.py              # 启动入口
├── app/
│   ├── db.py           # SQLite schema 与线程安全事务
│   ├── services.py     # 状态机与全部业务规则
│   ├── server.py       # HTTP 服务与 REST API
│   ├── adapters.py     # 配送 / 付款模拟适配器
│   ├── reminders.py    # 进程内时限提醒
│   └── seed.py         # 虚构客户演示数据 + SVG 占位照片
├── web/                # 前端（亚麻白 / 布艺蓝 / 暖灰）
├── tests/test_core.py  # 编号唯一 / 配包完整 / 状态顺序 / 重复验收 / 赔付权限
├── data/               # 运行生成的 SQLite（git 忽略）
└── photos/             # 拆前 / 洗后 / 复装照片（git 忽略）
```
